Concepts

How it works

The idea

Plants already run an inner loop: an advanced controller, the autopilot, holds the process at its targets every minute. The autopilot is only as good as its model, its sensors and its targets, and all three go stale. Equipment fouls, instruments drift, seasons change, and operators lose trust and switch it off. Keeping it at its best is an outer loop that today runs on people: an engineer who finds the time every few weeks or months. This simulator shows what happens when an AI agent inside a harness runs that outer loop every day, and why the harness, not the AI, is what makes it safe.

The plant

A 300 kg tank is fed with cold water and heated by a 90 kW electric element. Hot water goes to a downstream process that pays more the hotter it is, so the profitable place to run is just below boiling. At 99 °C an independent switch raises an alarm; at 100 °C a safety system cuts the heater. The physics is one energy balance: M·cp·dT/dt = F·cp·(Tin − T) + η·Q − UA·(T − Tamb).

Three things go wrong slowly, as they do in real plants:

  • Scale builds up on the element, so the heating efficiency η falls. The autopilot's model still assumes a clean element, so control gets sloppier and electricity is wasted; in winter the heater can run out of power.
  • The sensor drifts and reads low. The autopilot thinks the water is cooler than it is and pushes it towards boiling.
  • Winter brings colder inlet water, so the heater works harder.

Operators react the way people do. After a high-temperature alarm they take 2 °C off the setpoint; after three alarms in a day, or a boil trip, they switch the autopilot to manual and run the heater cautiously by hand. That loss of trust is often what really costs money.

Three ways to run the outer loop

WhoWhat happens
NobodyThe autopilot runs on its day-one settings for ever.
EngineerEvery few weeks, a generous engineer review: perfect information from a step test, the sensor recalibrated, the element descaled when needed, the model updated, operators put back on the autopilot and the target reset to 95 °C. The only handicap is how often there is time for it.
AI agentEvery morning at 06:00 an agent reviews yesterday with the data an engineer would use, proposes changes, tests them on a digital twin and routes them through the harness.

The agent harness

The agent's brain only reasons and proposes. Everything that keeps it safe is ordinary code around it, in src/agent/harness.js.

Harness partIn this simulator
ToolsRead-only: the daily report from the historian, a sensor check against operators' handheld readings, model re-identification from an energy balance and a digital-twin backtest. No tool can reach the safety system.
GuardrailsAn approved envelope: target 85–97 °C, model efficiency 0.5–1.05, sensor correction ±3 °C, and a maximum change per review.
Independent checkThe harness re-runs yesterday on its own twin with the proposed settings and blocks anything that raises the boiling risk, whatever the brain claimed.
Trust ladderAdvisor: recommends only. Co-pilot: an engineer approves each change. Bounded autopilot: small software changes inside the envelope go live on their own, and you can undo them; maintenance and larger steps still need a person.
Monitoring and rollbackThe next morning the harness compares the day after an automatic change with the day before. More alarms, a trip or much worse control, and it puts the old settings back.
Audit trail and memoryEvery tool call, decision and change is logged. The brain is told what it changed recently and what happened next.

Two brains, one harness

Built-in rules (src/agent/rule-brain.js) do what a good APC engineer does each morning, deterministically and free. Claude (src/agent/claude-brain.js) gets the same tools and a description of the plant, and decides for itself what to check and what to propose. Both go through exactly the same guardrails, twin check and approvals: swap the brain, keep the safety.

Run it yourself

npm start serves the app on http://localhost:5173. npm test runs the tests and npm run compare prints the three-strategy scorecard in the terminal. There is no build step and there are no dependencies.
